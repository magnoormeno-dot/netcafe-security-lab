# Case Studies

This directory contains anonymized defensive case studies for internet cafe and gaming venue security.

Case studies must remove venue names, customer names, staff identities, vendor names, IP addresses, serial numbers, screenshots, credentials, and any details that would enable abuse. The goal is to document defensive lessons, not to expose victims or publish bypass methods.

## Contents

| File | Purpose |
| --- | --- |
| `TEMPLATE.md` | Submission template for future cases. |
| `0001-anonymized-pattern.md` | Fully anonymized example case study. |
| `0002-synthetic-false-positive-tuning.md` | Synthetic case study showing evidence-backed tuning for a benign vendor update. |

## Review Rules

- Keep the write-up vendor-neutral unless disclosure is coordinated and approved.
- Pair every attack-pattern description with detection and mitigation.
- Avoid reproduction steps that enable billing bypass.
- Preserve operational lessons: logs that mattered, controls that failed, controls that worked, and follow-up actions.
