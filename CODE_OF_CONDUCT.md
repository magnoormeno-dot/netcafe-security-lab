# Code of Conduct

CafeSec Lab is a defensive security project. We expect contributors to behave with the care required when discussing real operators, real software vendors, and real abuse patterns.

This code of conduct is adapted from the [Contributor Covenant 2.1](https://www.contributor-covenant.org/version/2/1/code_of_conduct/).

## Our Standards

Examples of behavior that contributes to a healthy research community include:

- using welcoming and inclusive language;
- respecting different levels of professional experience;
- giving and accepting constructive feedback;
- focusing criticism on evidence, methodology, and safety impact;
- treating venue operators, vendors, researchers, and affected users with dignity.

Unacceptable behavior includes:

- harassment, intimidation, or discriminatory language;
- publishing exploit instructions, credentials, private vendor correspondence, or sensitive operator details;
- pressuring maintainers to disclose before a coordinated disclosure window has ended;
- using the project to recruit for unauthorized access, fraud, cheating, or gray-market services;
- misrepresenting test results, deployment claims, or professional credentials.

## Security Research Expectations

Research discussions must stay defensive. If a contribution describes attacker behavior, it must also describe realistic detection, prevention, containment, or verification steps.

Do not include live targets, vendor secrets, customer names, screenshots of private systems, or reproduction material that would let a reader bypass billing or access controls.

## Enforcement

Maintainers may edit, reject, hide, or remove contributions that violate this policy. Repeated or severe violations may result in a ban from the project spaces.

To report conduct concerns, contact `contact@cafeseclab.com`. For vulnerability reports, use the process in [`.github/SECURITY.md`](.github/SECURITY.md) instead of this channel.
